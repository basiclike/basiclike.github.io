A-1강. Code 탭에서 Claude에게 파일 만들게 하기

Code 탭에서 내 PC의 학습 기록 폴더를 열고, Claude가 파일을 만들기 전에 승인 화면에서 만들 파일의 위치와 내용을 읽어 승인할 수 있습니다.

A. Code 탭으로 Claude에게 일 시키기 구현 중심 · 예상 학습 시간 약 40분

0. 학습 목표

더보기
  • Code 탭에서 내 PC의 학습 기록 폴더를 열고, Claude가 파일을 만들기 전에 승인 화면에서 만들 파일의 위치와 내용을 읽어 승인할 수 있습니다.
  • 승인 화면에서 원하지 않는 작업(파일 지우기)을 알아보고 거절한 뒤, 폴더가 그대로인지 탐색기로 확인할 수 있습니다.
  • Claude가 만든 파일을 메모장으로 열어 승인 화면에서 읽은 내용, 폴더의 실제 파일 목록과 대조해 채택하거나 고치게 할 수 있습니다.

 

1. 시작하기 전에

→ 제공된 시작 자료를 C:\study-notes에 풀고, 이 강의에서 쓸 환경을 확인합니다.

더보기

C:\study-notes에는 학습 노트 파일 아홉 개가 들어갑니다. 이 폴더를 처음 보는 사람은 ai-tools.md, kiosk-facts.md 같은 파일 이름만 보고, 무엇이 들었는지는 파일을 하나씩 열어야 압니다. 이 대주제에서는 이 폴더를 GitHub에 올리고 사이트로 만듭니다. 이번 강의에서는 그 첫 단계로 Claude 데스크톱 앱의 Code 탭에서 이 폴더를 열고, 파일마다 무엇이 들었는지 적은 README.md를 Claude에게 만들게 합니다. 이 강의의 중심은 Claude가 파일을 만들기 전에 보여 주는 승인 화면을 읽고 승인하거나 거절하는 것입니다. B-1강부터 Claude에게 시키는 Git 명령도 모두 같은 승인 화면에서 읽습니다.

 

💡 사용 환경

항목 값
Claude 데스크톱 앱 Code 탭, Environment Local, 권한 모드 Manual
요금제 Claude Pro
작업 폴더 C:\study-notes
확인용 편집기 메모장
저장소 GitHub Free 계정, 공개 저장소 study-notes, 브랜치 main
GitHub 로그인 GitHub CLI(gh auth login)
사이트 GitHub Pages, Deploy from a branch, main, /(root), 주소 <사용자 이름>.github.io/study-notes/

 

Claude Pro 요금제 계정과, 설치해 로그인한 Claude 데스크톱 앱은 Claude 강의에서 준비한 것을 그대로 씁니다. 학습 노트 파일은 제공된 study-notes.zip에 들어 있습니다. 이 파일의 압축을 C:\에 풀면 C:\study-notes 폴더가 생깁니다.

 

▶ 지금 해보세요

  1. 탐색기를 열고 주소 칸에 C:\를 입력한 뒤 Enter 키를 누릅니다. 목록에 study-notes 폴더가 이미 있으면(다른 강의에서 만든 폴더 등) 그 폴더를 클릭하고 F2 키를 눌러 이름을 study-notes-old로 바꿉니다.
  2. study-notes.zip을 다운로드한 폴더를 열고, study-notes.zip을 오른쪽 클릭한 뒤 Extract All...을 클릭합니다.
  3. 열린 창에서 압축을 풀 위치 칸(Files will be extracted to this folder: 아래)의 글을 모두 지우고 C:\를 입력한 뒤 Extract를 클릭합니다.
  4. 탐색기 주소 칸에 C:\study-notes를 입력하고 Enter 키를 누릅니다.
  5. 파일이 아홉 개인지 읽습니다. 이름순으로 ai-tools.md, folder-index.md, kiosk-facts.md, kiosk-project.md, kiosk-research.docx, kiosk-research.md, model-notes.md, prompt-notes.md, study-guide.md입니다.
  6. 시작 메뉴에서 Claude 앱을 열고 Claude Pro 요금제 계정으로 로그인되어 있는지 봅니다.

 

2. 내 PC에서 실행되는 Code 탭

→ 이 대주제가 채팅이나 Cowork 대신 Code 탭을 쓰는 이유와, 실행 전에 묻는 권한 모드를 알아봅니다.

더보기

Claude의 채팅은 파일을 첨부해야 읽고, 만든 결과는 내가 옮겨 저장해야 했습니다. Cowork는 연결한 폴더를 읽고 쓰지만, 2026-10-06부터 Pro 요금제의 새 Cowork 작업은 Anthropic 서버에서 실행되고 내 폴더에서는 필요한 파일의 사본만 가져갑니다. 같은 도움말은 내 PC에서 실행해야 하는 일에는 데스크톱 앱의 Claude Code를 쓰라고 안내합니다(Claude 도움말: Use Claude Cowork on web, desktop, and mobile, 2026-10-06 조회). B 소주제에서 쓰는 Git은 폴더 안에 기록을 쌓는 프로그램이라 내 PC의 폴더에서 실행되어야 합니다. 그래서 이 대주제는 데스크톱 앱의 Code 탭을 씁니다. Code 탭이 Claude Code이고, 실행 환경을 Local로 고르면 Claude가 내 PC에서 고른 폴더의 파일에 직접 접근합니다(Claude Code 문서: Get started with the desktop app, 2026-10-06 조회). Code 탭은 Pro 이상 요금제에서 쓸 수 있고, 채팅과 같은 사용량 한도를 함께 씁니다.

 

Code 탭에서 Claude는 파일을 만들거나 고치거나 명령을 실행하기 전에 권한 모드에 따라 묻습니다. 폴더의 파일 목록을 보려고 명령을 실행할 때도 묻습니다. 권한 모드 Manual은 매번 묻는 모드입니다. 바뀔 내용을 먼저 보여 주고, 내가 승인해야 실행하고, 거절하면 실행하지 않고 어떻게 할지 다시 묻습니다(Claude Code 문서: Desktop, 2026-10-06 조회). 이 대주제는 처음부터 끝까지 Manual로 합니다. 이 장치가 막지 못하는 것도 있습니다. 승인 화면을 읽지 않고 승인하면 원하지 않는 변경도 그대로 실행됩니다. 그래서 이 강의는 승인 화면에서 무엇을 읽고 무엇으로 판단하는지를 연습합니다.

 

3. Code 탭에서 학습 기록 폴더 열기

→ Code 탭에서 새 세션을 열고 Local, C:\study-notes, 권한 모드 Manual을 고릅니다.

더보기

데스크톱 앱 왼쪽 위, 사이드바 위에 아이콘 두 개가 있습니다. 말풍선 모양은 채팅이고 </> 모양이 Code 탭입니다. Code 탭에서 Claude와 나누는 대화 하나를 세션이라고 부릅니다. 세션은 사이드바의 New로 시작합니다. 첫 요청을 보내기 전에 입력창 위와 아래에서 네 가지를 고릅니다. 입력창 바로 위의 칩 두 개는 Environment(어디서 실행할지)와 폴더(어느 폴더에서 일할지)이고, 입력창 아래 왼쪽은 권한 모드(실행 전에 얼마나 물을지), 아래 오른쪽은 모델입니다.

 

▶ 지금 해보세요

  1. Claude 데스크톱 앱 왼쪽 위의 </> 아이콘을 클릭해 Code 탭으로 갑니다. 요금제를 올리라는 안내가 나오면 Pro 요금제가 아닌 계정이므로 이 강의 끝의 막혔을 때 표를 봅니다.
  2. 사이드바의 New를 클릭합니다.
  3. 입력창 바로 위 첫째 칩이 Local인지 읽습니다. 다른 값이면 클릭하고, 펼쳐진 목록(Local, Cloud, Remote Control, WSL, SSH)에서 Local을 클릭합니다. 내 PC에서 실행한다는 뜻입니다.
  4. 둘째 칩(폴더 이름)을 클릭하고 폴더를 고르는 항목을 클릭합니다. 폴더를 고르는 창이 열리면 주소 칸에 C:\study-notes를 입력해 이동하고, study-notes 폴더를 선택한 뒤 폴더 선택 버튼을 클릭합니다.
  5. 입력창 아래 왼쪽의 권한 모드(처음에는 Auto로 보입니다)를 클릭하고, 제목이 Mode인 목록에서 Manual을 클릭합니다. 입력창 아래에 Manual이 보이면 됩니다.
  6. 입력창 위 둘째 칩에 고른 폴더 이름 study-notes가 보이는지 읽습니다. 다른 폴더 이름이 보이면 4번으로 돌아갑니다.
  7. 입력창 아래 오른쪽의 모델과 그 옆 설정은 바꾸지 않습니다.

 

[화면 캡처: img_01 — Code 탭에서 첫 요청을 보내기 전. Environment Local, 고른 폴더 study-notes, 권한 모드 Manual이 보이는 입력창]

 

▲ 세션을 시작하기 전에 고르는 네 가지

 

권한 모드 목록에는 Auto, Manual, Accept edits, Plan이 있고 맨 아래에 Bypass permissions가 있습니다. 새 세션의 기본값은 Auto이고, Auto는 승인 화면 없이 Claude가 판단해 진행합니다. Accept edits는 파일 변경을 묻지 않고 적용합니다. 이 강의의 연습 자리를 없애므로 Manual 말고는 고르지 않습니다. 권한 모드는 첫 요청을 보내기 전에 바꿉니다. 새 세션을 열 때마다 입력창 아래가 Manual인지 읽습니다.

 

4. 파일을 만들게 하고 승인 화면 읽기

→ Claude에게 README.md를 만들게 하고, 승인 화면에서 경로와 내용을 읽은 뒤 승인합니다.

더보기

README.md는 폴더를 처음 여는 사람이 가장 먼저 읽는 설명 파일입니다. B-3강에서 이 폴더를 GitHub에 올리면 저장소 화면의 파일 목록 아래에 이 파일의 내용이 보입니다. 아래 요청을 보냅니다. 둘째 줄은 워드 파일을 열지 말라는 조건입니다. 워드 파일은 글자만 든 파일이 아니라서 Claude가 열려면 명령을 따로 실행할 수 있는데, 이 강의에서는 파일을 만드는 승인 하나에 집중합니다.

 

클로드 프롬프트

이 폴더의 파일 목록을 읽고, 파일마다 무엇이 들었는지 한 줄씩 적은 README.md를 만들어 줘. 맨 위 줄은 # 학습 기록.
워드 파일(.docx)이 있으면 열지 말고, 이름이 같은 .md 파일을 워드 문서로 만든 것이라고만 적어 줘.

 

Claude가 폴더의 파일 목록을 보려고 명령을 실행하면 명령 승인 화면이 먼저 나옵니다. 이 화면은 표 아래 문단의 방법으로 읽고 승인합니다. README.md를 만들 차례가 되면 Claude는 멈추고 입력창 위에 파일 승인 화면을 보여 줍니다. 제목은 Allow Claude to write README.md?이고, 그 아래 회색 칸에 만들 파일의 전체 경로, 그 아래에 들어갈 내용이 보입니다. 새로 들어가는 줄은 줄 앞에 +가 붙고 바탕이 초록색입니다. 버튼은 왼쪽의 Deny(거절), 오른쪽의 Always allow와 Allow once(이번 한 번 승인)입니다.

 

승인 화면에서 읽을 것 맞는 값 다르면
회색 칸의 경로 C:\study-notes\README.md 다른 폴더이거나 다른 이름이면 거절한다
내용의 맨 위 줄 # 학습 기록 거절하고 맨 위 줄을 다시 알려 준다
내용에 적힌 파일 이름 탐색기의 C:\study-notes 목록에 있는 이름들 폴더에 없는 이름이 적혔거나 있는 파일이 빠졌으면 거절하고 그 이름을 알려 준다

 

▶ 지금 해보세요

  1. 위 요청을 입력창에 붙여 넣고 Enter 키를 누릅니다.
  2. 승인 화면이 나오면 버튼을 클릭하기 전에 위 표의 세 가지를 차례로 읽습니다. 파일 이름은 탐색기의 C:\study-notes 창을 옆에 두고 하나씩 견줍니다.
  3. 셋이 모두 맞으면 Allow once를 클릭합니다. Always allow는 클릭하지 않습니다. 그다음부터 파일 변경을 묻지 않게 되어 이 대주제의 확인 자리가 없어집니다.
  4. 하나라도 다르면 Deny를 클릭합니다. Claude가 어떻게 할지 물으면 다른 점을 한 줄로 보냅니다. 예: kiosk-facts.md 줄이 빠졌어. 폴더에 있는 파일을 모두 적어 줘. 새 승인 화면이 나오면 2번부터 다시 합니다.
  5. Claude가 파일을 만들었다고 답하면 다음 절로 갑니다.

 

[화면 캡처: img_02 — README.md를 만드는 승인 화면. 제목 Allow Claude to write README.md?, 경로 C:\study-notes\README.md, # 학습 기록으로 시작하는 초록 줄, Deny·Always allow·Allow once 버튼이 보이는 상태]

 

▲ 파일을 만들기 전에 보이는 승인 화면

 

명령 승인 화면은 제목이 Allow Claude to run <명령 설명>?이고, 회색 칸에 실행할 명령 줄이 있고, 버튼은 Deny와 Allow once입니다. 제목의 설명은 Claude가 붙인 문장이므로 명령 줄도 함께 읽습니다. 지우기, 옮기기, 이름 바꾸기를 뜻하는 낱말(rm, del, Remove-Item, mv, move, Move-Item, ren, Rename-Item)이 없고 파일 목록이나 내용을 보는 명령이면 승인합니다. 무엇을 하는 명령인지 모르겠으면 거절하고 이 명령이 무엇을 하는지 먼저 한 줄로 알려 줘.라고 보냅니다. Allow once 오른쪽 화살표를 펼치면 나오는 Allow and switch to Auto(승인하고 Auto로 바꾸기)와 파일 승인 화면의 Always allow는 고르지 않습니다. 이 대주제에서는 매번 읽고 한 번씩 승인합니다.

 

5. 탐색기와 메모장으로 대조하기

→ Claude가 "만들었다"고 답한 것은 확인이 아닙니다. 폴더에 파일이 실제로 생겼는지, 내용이 승인 화면에서 읽은 것과 같은지는 내 PC에서 직접 봅니다.

더보기

▶ 지금 해보세요

  1. 탐색기의 C:\study-notes 창을 클릭하고 F5 키를 눌러 목록을 새로 고칩니다. README.md가 생겨 파일이 열 개인지 읽습니다.
  2. 메모장을 열고 파일 > 열기를 클릭한 뒤, 파일 형식을 모든 파일로 바꿔 C:\study-notes\README.md를 엽니다.
  3. 맨 위 줄이 # 학습 기록인지 읽습니다.
  4. 적힌 파일 이름을 위에서 아래로 읽으며 탐색기 목록과 하나씩 견줍니다. 승인 화면에서 읽은 이름들과도 같은지 봅니다.
  5. 설명이 실제 내용과 다른 줄이 있으면 Code 탭에 한 줄로 고치게 합니다. 예: README.md에서 model-notes.md 줄의 설명이 틀렸어. 요금제 한도 기록과 모델 기준표라고 고쳐 줘. 고치는 승인 화면에서 바뀌는 줄이 그 줄 하나뿐인지 읽고 승인합니다.

 

이 파일을 채택하는 근거는 탐색기의 실제 목록과, 메모장으로 열어 본 시작 자료 파일의 내용입니다. Claude의 설명 문장이 그럴듯해도 폴더에 없는 파일 이름이 적혀 있으면 채택하지 않습니다. 설명 문장은 매번 다르게 나오므로 남의 README.md와 문장이 달라도 괜찮습니다.

클로드 프롬프트

▶ 지금 해보세요

  1. 위 요청을 보냅니다.
  2. Claude가 정말 지울지 글로 되묻으면 응, 지워 줘.라고 보냅니다. 승인 화면이 나오게 하려는 것입니다.
  3. 승인 화면의 제목 줄을 읽습니다. Delete, Remove, Recycle Bin처럼 지우기를 뜻하는 영어 낱말이 있는지 봅니다.
  4. 회색 칸의 명령 줄에서 README.md와 지우기를 뜻하는 낱말(Delete, Remove, Recycle, del, rm 가운데 하나)을 찾습니다. 둘이 함께 있으면 이 명령은 파일을 지우는 명령입니다.

  6. Claude가 어떻게 할지 물으면 지우지 말고 그대로 둬.라고 보냅니다.
  7. 탐색기의 C:\study-notes 창에서 F5 키를 누르고 README.md가 그대로 있는지 읽습니다.

 

지우는 명령의 모양은 매번 다를 수 있습니다. Remove-Item이나 rm이 보일 때도 있고, 파일을 휴지통으로 보내는 DeleteFile 명령이 보일 때도 있습니다. 그래서 낱말 하나만 찾지 않고 제목 줄과 명령 줄을 함께 읽습니다. 명령 줄에 지우기 낱말과 내 파일 이름이 함께 있으면 거절합니다. Claude가 지울 파일이 없다고 답하면 앞 절의 README.md가 만들어지지 않은 것이므로 앞 절을 다시 합니다.

 

실수로 승인해 README.md가 지워졌으면 앞 절의 요청을 다시 보내 새로 만들게 하고, 승인 화면을 읽은 뒤 승인합니다.
