C#과 WPF 다루기

C#으로 코드를 쓰고 WPF로 화면을 만드는 일 자체에 익숙해지는 것이 목표입니다. 화면을 구성하고, 값을 주고받고, 오래 걸리는 작업 중에도 창이 멈추지 않게 만드는 것까지 해 봅니다.

AI 추론을 내 서비스에 붙이기

모델을 새로 만드는 것이 아니라, 판정 기능을 내 프로그램의 흐름 안에 넣는 방법을 익힙니다. 추론이 실패하거나 느릴 때 프로그램이 어떻게 버텨야 하는지도 정해 봅니다.

DB 트랜잭션 이해하기

여러 표를 함께 바꾸는 작업이 중간에 실패하면 무슨 일이 벌어지는지 직접 겪어 봅니다. 하나의 트랜잭션으로 묶고, 실패하면 되돌리는 처리를 만들어 눈으로 확인합니다.

다음 세 가지는 반드시 갖춥니다. 하나라도 빠지면 완료로 보지 않습니다.

C# WPF UI

  • WPF로 화면을 만듭니다.
  • 화면과 처리 로직을 분리하고, 처리 중에 화면이 멈추지 않게 합니다.
  • 판정 결과와 이력을 화면에서 확인할 수 있게 합니다.

AI 추론

  • 영상이나 이미지를 입력으로 판정 결과와 신뢰도를 반환합니다.
  • 추론은 판정만 하고 업무 데이터를 직접 바꾸지 않습니다.
  • 사용한 모델 이름과 버전을 판정 결과와 함께 저장합니다.

DB 트랜잭션

  • 판정 결과와 업무 데이터를 하나의 트랜잭션으로 저장합니다.
  • 처리 도중 실패하면 전체를 롤백합니다.
  • 롤백이 실제로 동작하는 것을 완료 보고서에서 보입니다.

세 가지를 각각 어디에 어떻게 구현했는지 개발 계획서와 완료 보고서에서 짚어 줍니다.

설계 요구사항

  • 클라이언트, 서버, AI 추론, 데이터베이스의 책임을 나눕니다. 클라이언트에서 데이터베이스에 직접 접근하지 않습니다.
  • 길이 접두사 방식의 TCP 메시지 경계 처리와 JSON 요청·응답 규격을 정의합니다.
  • 여러 클라이언트가 동시에 접속하는 경우와 연결이 끊겼다 다시 연결되는 경우를 처리합니다.
  • 화면과 처리 로직을 분리합니다. 처리 중에 화면이 멈추지 않아야 합니다.
  • AI 추론은 판정만 수행하고 업무 데이터를 직접 변경하지 않으며, 데이터베이스 트랜잭션 밖에서 수행합니다.
  • 판정 결과와 업무 데이터(이력, 집계, 수량 등)를 하나의 트랜잭션으로 저장하고, 처리에 실패하면 전체를 롤백합니다.
  • 판정에 사용한 모델 이름과 버전을 판정 결과와 함께 저장합니다.
  • 판정 이력의 조건 검색과 페이징을 구현합니다.
  • 카메라가 없거나 연결이 끊겼을 때를 처리하고, 사용이 끝난 장치 자원을 해제합니다.
  • 예외 상황(잘못된 입력, 연결 실패, 추론 실패, 데이터베이스 오류)을 처리합니다.
  • 이 밖의 설계는 팀에서 정하고, 진행하며 달라진 것은 완료 보고서에 반영합니다.

AI 추론 위치 (택 1)

  • 1안: WPF 클라이언트가 C# 서버에 요청하고, 서버 안에서 AI 추론을 하고, 서버가 MySQL에 저장합니다.
  • 2안: WPF 클라이언트가 C# 서버에 요청하고, 서버가 Python AI 추론 서버를 부르고, 서버가 MySQL에 저장합니다.

1안은 언어 하나로 끝나고 실행과 배포가 단순합니다. 2안은 학습과 추론을 Python으로 하므로 학습한 모델을 그대로 쓸 수 있지만 서버가 하나 늘어납니다.

팀원이 2명인 팀은 1안을 권합니다. 어느 쪽을 골랐는지와 그 이유를 개발 계획서에 적습니다.
