익힐 것

→ 이 프로젝트의 학습 핵심 두 가지를 알아봅니다.

DB 트랜잭션

여러 표를 함께 바꾸는 작업이 중간에 실패하면 무슨 일이 벌어지는지 직접 겪어 봅니다. 하나의 트랜잭션으로 묶고, 실패하면 되돌리는 처리를 만들어 눈으로 확인합니다.

지난 팀 프로젝트에서는 서버가 트랜잭션을 맡았습니다. 이번에는 혼자 처음부터 끝까지 만들어 봅니다.

AI 사용 개인 노하우 만들기

GPT, Claude, Gemini, Grok 중 무엇을 쓰든, 결과의 기준과 완료 조건이 먼저 갖춰진 상태에서 AI에게 일을 시키는 연습을 합니다. 스스로 답을 찾을 질문은 네 가지입니다.

  • 어떤 명령을 주는가
  • 어떤 순서로 주는가
  • 어떤 산출물을 먼저 만들게 하는가
  • 어떤 지침과 규칙을 미리 주는가

정답은 없습니다. 이번 프로젝트에서 자기 방법을 만들고, 그 방법이 통했는지 안 통했는지를 개발일지와 완료 보고서에 적습니다. AI가 만든 코드를 그대로 붙이고 넘어가면 이 학습 목표는 달성되지 않습니다. 자세한 내용은 AI 사용 방법과 결과에 있습니다.

프로젝트 주제

→ 주제는 자유이고, 트랜잭션을 쓸 자리가 있는 주제를 고릅니다.

주제는 자유입니다. 데이터를 저장하고 바꾸는 프로그램을 혼자 만듭니다.

주제를 정할 때 확인할 것

무엇을 만들지 정할 때 다음 세 가지를 확인합니다.

  • 표가 두 개 이상 필요한가
  • 한 번의 작업으로 두 표가 함께 바뀌는 자리가 있는가
  • 그 작업이 중간에 실패하면 데이터가 어긋나는가

세 가지에 모두 해당하면 DB 트랜잭션을 쓸 자리가 있는 주제입니다. 예를 들어 주문과 재고, 대여와 보유 수량, 입금과 잔액 같은 것입니다.

이전 프로젝트에서 작성한 데이터베이스 코드와 화면 코드를 확장하는 형태로 진행해도 무방합니다.

필수 요구사항

→ 반드시 갖출 세 가지입니다. 하나라도 빠지면 완료로 보지 않습니다.

DB 트랜잭션

  • 한 번의 작업으로 두 개 이상의 표를 함께 바꿉니다
  • 처리 도중 실패하면 전체를 롤백합니다
  • 롤백이 실제로 동작하는 것을 완료 보고서에서 보입니다

화면

  • 사람이 쓰는 화면이 있습니다. 콘솔만으로는 완료로 보지 않습니다
  • 입력값이 잘못되었을 때 화면에서 알려 줍니다
  • 저장한 데이터를 화면에서 다시 볼 수 있습니다

AI 사용 기록

  • 무엇을 어떤 순서로 요청했는지 적습니다
  • 무엇이 통했고 무엇이 안 통했는지 적습니다
  • 어디를 왜 고쳤는지 적습니다

세 가지를 각각 어디에 어떻게 구현했는지 개발 계획서와 완료 보고서에서 짚어 줍니다.

개발 환경

→ 데이터베이스만 필수이고 나머지는 자유입니다.

항목 정하는 방법
데이터베이스 필수. MySQL, SQLite, MongoDB 중 자유
언어 자유. C#, Python, C++ 무엇이든 됩니다
화면 자유. WPF, PySide6, Qt, 웹 무엇이든 됩니다
개발 도구 자유
형상 관리 Git, GitHub
AI 도구 GPT, Claude, Gemini, Grok 중 자유

고른 것과 그 이유를 개발 계획서에 적습니다. 익숙한 것을 골라도 되고, 새로 배워 볼 것을 골라도 됩니다.

설계 요구사항

→ 설계에서 지킬 조건과 팀이 정할 여지를 확인합니다.

  • 표가 두 개 이상이고, 표 사이의 관계를 ERD로 그릴 것
  • 화면과 데이터베이스 처리를 분리할 것
  • 트랜잭션으로 묶는 작업이 무엇인지 문서에 표시할 것
  • 예외 상황 처리(잘못된 입력, 연결 실패, 데이터베이스 오류)
  • 이 밖의 설계는 각자 정하고, 진행하며 달라진 것은 완료 보고서에 반영

이번 프로젝트에서만 쓰는 산출물

→ 이 공지에서만 쓰는 산출물 셋을 설명합니다.

만들 것

무엇을 만드는지, 누가 쓰는지 개발 계획서에 적습니다.

트랜잭션 목록

트랜잭션 목록이 이번 프로젝트의 중심입니다. 어떤 작업이 어떤 표를 함께 바꾸는지 먼저 정하고 코드를 씁니다. 함께 바뀌는 표와 실패했을 때 되돌릴 것을 목록으로 적습니다.

롤백 확인

롤백 확인을 빼면 완료로 보지 않습니다. 일부러 실패를 만들어 되돌아가는 것을 보이면 됩니다.

참고 사항

→ 데이터와 코드를 쓸 때 지킬 것입니다.

  • 데이터는 직접 만들어도 되고 공개 데이터를 써도 됩니다
  • 실제 사람의 이름, 연락처, 주소를 넣지 않습니다
  • 공개된 코드를 가져오면 어디서 가져왔는지 적습니다
  • 이전 프로젝트에서 작성한 데이터베이스 코드와 화면 코드를 써도 됩니다
