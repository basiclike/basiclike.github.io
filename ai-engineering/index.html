7. AI Engineering

소주제 5개 · 강의 21편

Claude Code에게 개발을 그냥 맡기면 무엇이 빠지는지 직접 겪어 보고, 사람 개발자가 같은 실수를 막으려고 만든 요구사항, 설계, 구현, 검증의 차례를 왜 AI에게도 시켜야 하는지 알아봅니다. 비슷하지만 서로 다른 Skill 구조 셋을 읽고 줄인 판을 직접 만들어, 그 Skill로 키오스크 문서로 답하는 RAG 챗봇을 문서와 테스트를 남기며 개발해 봅니다. 끝으로 세 방식을 비교하고 Skill로 막지 못하는 것은 hook으로 막아, 내 일에 맞는 개발 방법을 꾸려 봅니다.

→ 여기서 시작하세요: Claude Code 대주제를 마친 뒤 1강부터 차례로 따라 하면 됩니다. Claude Code와 Git이 깔린 Windows PC가 필요하고, Python은 몰라도 괜찮습니다. 코드는 Claude Code가 쓰고 여러분은 요청하고 결과를 확인합니다.

AAI에게 그냥 맡기면 생기는 일과 실습 준비

Claude Code에게 챗봇을 한 번에 맡겨 보고 결과에서 결점을 찾아봅니다. 개발 방법과 하네스가 왜 필요한지, RAG가 무엇을 푸는지 알아보고, 실습 저장소를 준비해 같은 요청을 기본 흐름과 확인 수단으로 다시 맡겨 봅니다.

  1. 1강 Claude Code에게 챗봇을 한 번에 맡겨 보기빈 폴더에서 Claude Code에게 "문서로 답하는 챗봇 만들어 줘" 한 문장만 보내 보고, 결과를 실행해 요청하지 않은 덧붙임, 확인 없는 완료 보고, 추측으로 채운 조건을 찾아 문제 목록으로 적어 봅니다. 공개 약 50분
  2. 2강 왜 AI에게 개발 방법을 시켜야 하나1강의 문제 목록을 사람 개발자가 겪은 같은 실수와 나란히 놓고, 요구사항, 설계, 구현, 검증이라는 개발 방법이 왜 생겼는지 알아봅니다. CLAUDE.md, Skill, hook, 권한 같은 장치가 각각 어떤 실수를 막는지, 그중 무엇이 부탁이고 무엇이 강제인지도 살펴봅니다. 비밀번호 약 45분
  3. 3강 RAG는 무엇을 푸는가모델이 모르는 키오스크 문서를 물으면 그럴듯하게 지어내는 장면에서 출발해, 문서를 나누고 벡터로 바꿔 찾은 조각을 근거로 답하는 RAG의 흐름을 그림 한 장으로 알아봅니다. 문서를 통째로 넣는 길과 비교해 이 실습에서 RAG를 만드는 이유도 따져 봅니다. 비밀번호 약 40분
  4. 4강 실습 저장소와 CLAUDE.md 준비하기Ollama를 설치해 `bge-m3`와 답변 모델을 받고, Claude Code에게 Python 3.14와 실습 저장소 `C:\kiosk-chatbot`의 가상환경, 테스트 도구, Git을 준비시켜 봅니다. 키오스크 마크다운 문서만 옮겨 넣고, 테스트를 가상환경에서 돌리라는 규칙을 CLAUDE.md에 적어 봅니다. 비밀번호 약 60분
  5. 5강 기본 흐름과 확인 수단1강의 챗봇 요청을 이번에는 Claude가 나를 인터뷰해 `SPEC.md`로 쓰게 하고, 탐색, 계획, 구현, 커밋의 흐름으로 첫 작은 기능을 맡겨 봅니다. 끝났다는 말 대신 Claude가 스스로 돌린 테스트 출력을 증거로 보고하게 하고, `/goal`로 끝낼 조건을 걸어 봅니다. 비밀번호 약 55분

B정해진 절차대로 만들기

정해진 절차를 따르게 하는 Skill 구조를 읽고 줄인 판을 만들어, 챗봇의 문서 불러오기와 벡터 저장을 그 Skill로 개발하며 설계 메모, 계획서, 테스트를 남겨 봅니다.

  1. 6강 절차형 Skill은 왜, 어떻게 만들어졌나Superpowers가 막으려는 결점과 brainstorming부터 브랜치 마무리까지 이어지는 차례, 남기는 문서를 읽어 봅니다. 금지 문장, 핑계와 반박 표가 왜 강하게 쓰였는지, 그래도 그것이 강제가 아니라 부탁인 이유도 알아봅니다. 비밀번호 약 45분
  2. 7강 절차형 Skill 줄인 판 만들기브레인스토밍, 계획, 테스트 먼저 Skill 셋을 `.claude/skills/`에 직접 만들어 봅니다. `description`과 `disable-model-invocation`을 정하고, 새 세션에서 Skill을 둔 판과 뺀 판으로 같은 요청을 보내 Skill이 켜지는지와 결과가 기준을 지키는지를 따로 재어 봅니다. 비밀번호 약 60분
  3. 8강 문서 불러오고 나누기를 절차대로 개발하기절차형 Skill로 요구 질문, 설계 메모, 계획서, 실패하는 테스트를 거쳐 키오스크 문서를 불러오고 조각으로 나누는 기능을 만들어 봅니다. 한국어 Windows에서 `encoding`을 빼면 무엇이 깨지는지, 조각 크기와 겹침이 무엇을 바꾸는지 실행 결과로 확인해 봅니다. 비밀번호 약 70분
  4. 9강 벡터로 바꿔 저장하고 계획과 대조하기같은 절차로 조각을 `bge-m3` 벡터로 바꿔 numpy 파일로 저장하는 기능을 더해 봅니다. 뜻이 가까운 문장일수록 점수가 높다는 것을 두 문장의 점수로 확인하고, 계획서와 결과를 대조해 빠진 단계와 계획에 없던 변경을 찾아봅니다. 비밀번호 약 70분

C필요한 기술만 꺼내 쓰기

필요할 때 하나씩 꺼내 쓰는 Skill 구조를 읽고, 묻기와 구조 개선 Skill을 만들어, 챗봇의 문서 찾기를 개발하고 다듬으며 결정 기록과 용어 문서를 남겨 봅니다.

  1. 10강 골라 쓰는 Skill은 왜, 어떻게 만들어졌나Matt Pocock skills가 막으려는 결점 넷과, 사람이 불러야 켜지는 Skill과 Claude가 스스로 고르는 Skill로 나뉜 짜임을 읽어 봅니다. 늘 켜진 절차형과 무엇이 다른지, 작은 Skill을 이어 붙여 명세에서 구현까지 가는 흐름도 살펴봅니다. 비밀번호 약 45분
  2. 11강 묻기 Skill과 결정 기록 만들기정하지 않은 조건을 권장 답과 함께 묻고, 용어는 `GLOSSARY.md`에, 되돌리기 어려운 결정은 ADR로 남기는 묻기 Skill을 직접 만들어 봅니다. 그 Skill로 문서 찾기 기능의 조건(몇 개를 찾을지, 무엇을 비슷하다고 볼지)을 정하고, 켠 판과 끈 판을 비교해 봅니다. 비밀번호 약 55분
  3. 12강 질문에 맞는 문서 찾기 개발하기묻기 Skill로 정한 조건과 테스트 먼저 Skill로 질문에 가까운 조각을 찾는 검색을 만들고, 일부러 빗나가게 쓴 질문으로 임베딩 검색이 놓치는 경우를 찾아봅니다. 한국어 조사를 뗀 BM25를 섞는 하이브리드 검색으로 그 빈틈을 메우고, recall@k를 pytest로 재 봅니다. 비밀번호 약 75분
  4. 13강 구조 개선 Skill로 검색 코드 다듬기구조 개선 Skill을 만들어, 엉킨 부분 후보와 이유를 받아 하나를 고르고 테스트는 그대로 둔 채 겉으로 드러나는 동작을 지키며 검색 코드를 다듬어 봅니다. 테스트가 통과해도 동작이 바뀔 수 있는 경우도 찾아봅니다. 비밀번호 약 60분

D명세를 기준으로 만들기

명세를 기준으로 삼는 Skill 구조를 읽고 줄인 판을 만들어, 챗봇이 출처를 붙이고 근거가 없으면 모른다고 답하게 개발하며 명세서, 대조 보고, 평가 세트를 남겨 봅니다.

  1. 14강 명세형 Skill은 왜, 어떻게 만들어졌나GitHub Spec Kit이 막으려는 결점을 발표 글, 설계 문서, converge 명령이 나온 순서로 따라가고, constitution부터 converge까지의 차례와 남는 파일을 읽어 봅니다. 변경분만 제안하는 OpenSpec과 비교해 명세를 기준으로 삼는다는 것이 무슨 뜻인지 알아봅니다. 비밀번호 약 45분
  2. 15강 명세 Skill 줄인 판 만들기Spec Kit을 연습 폴더에 설치해 원본 Skill을 열어 보고, 명세 쓰기, 빠진 조건 묻기, 작업 목록, 대조 Skill 넷의 줄인 판을 템플릿과 함께 만들어 봅니다. 켠 판과 끈 판으로 같은 기능의 명세를 받아 요구 번호, 수락 기준, 테스트 작업이 생기는지 비교해 봅니다. 비밀번호 약 70분
  3. 16강 출처 붙이기와 모르면 모른다고 답하기를 명세대로 개발하기"근거가 없으면 지어내지 않는다"를 명세의 요구와 수락 기준으로 적고, 찾은 조각에 번호를 붙여 답하고 출처를 다는 기능을 작업 목록대로 만들어 봅니다. 검색 점수가 낮으면 모델을 부르지 않는 코드와 모른다고 답하게 허락하는 프롬프트가 각각 무엇을 막는지 확인해 봅니다. 비밀번호 약 75분
  4. 17강 명세와 결과를 대조하고 빠진 요구 채우기내가 만든 대조 Skill을 새 컨텍스트의 리뷰 subagent에 맡기고, 같은 코드에 Spec Kit의 converge를 돌려 두 결과를 비교해 봅니다. 지키지 못한 명세 줄을 작업 목록에 되돌려 다시 구현하고, 완료 표시만 믿으면 무엇을 놓치는지 봅니다. 비밀번호 약 65분
  5. 18강 챗봇의 답을 평가하기앞에서 틀린 답과 직접 물어본 질문으로 평가 세트를 만들고, 검색은 recall@k를 pytest로, 답은 근거 충실도를 사람과 모델 채점으로 재 봅니다. 구조를 바꿨을 때 정말 좋아졌는지를 이 세트로 판단해 봅니다. 비밀번호 약 70분

E나만의 개발 방법 만들기

세 방식을 비교하고, Skill로 막지 못하는 것을 CLAUDE.md와 hook으로 막고, 조합한 내 방식으로 마지막 기능을 끝까지 만들어 봅니다.

  1. 19강 세 방식 비교하기절차형, 골라 쓰기, 명세형으로 개발하며 남긴 문서, 늘 실리는 맥락, 빠진 요구를 표로 비교하고, 일의 크기와 요구가 정해진 정도에 따라 어떤 방식이 맞는지 골라 봅니다. 비밀번호 약 45분
  2. 20강 Skill만으로 막지 못하는 것: CLAUDE.md와 hook테스트를 돌리지 않고 끝났다고 하는 일을 다시 겪어 보고, 같은 실수가 두 번이면 CLAUDE.md, 묻지 않고 매번 해야 하면 hook이라는 기준으로 장치를 골라 봅니다. 테스트가 통과하기 전에는 턴을 끝내지 못하게 하는 `Stop` hook과 커밋 전에 테스트를 거는 `PreToolUse` hook을 문장으로 요청해 만들게 하고, 막는지 확인해 봅니다. 비밀번호 약 70분
  3. 21강 내 방식으로 마지막 기능 끝까지 만들기고른 Skill과 hook을 묶은 내 방식으로 챗봇의 마지막 기능인 이어 묻는 대화를 요구사항부터 대조까지 만들어 봅니다. 진행 기록 파일과 기능 목록으로 세션을 넘기며 한 번에 기능 하나씩 통과시키고, 평가 세트로 확인한 뒤 README를 써서 대주제를 마무리합니다. 비밀번호 약 80분
