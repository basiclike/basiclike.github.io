1강. 첫 화면 만들기

실습 강의 ⏱ 약 50분

학습 목표

  • Claude Design 여는 방법
  • 기획서로 주문 첫 화면 요청하기
  • Claude가 되묻는 여섯 가지에 답하고 시안 고르기
  • 참고 화면에서 모양만 가져오기
  • 디자인 시스템 만들어 첫 화면에 입히기
  • 문구 다듬기와 고치는 세 방법
  • 고친 모양을 디자인 시스템에 남기기

준비

→ 이 강의에서 쓸 환경과 강의 자료를 확인하고, 따라 할 영상을 먼저 봅니다.

환경과 시간

Claude Work에서 쓴 기획서 kiosk-plan.md를 가지고 시작합니다. 기획서에 적은 주문 화면의 쓰는 사람과 화면의 목표, 첫 제작 범위(메뉴 선택부터 모의 주문 완료까지 다섯 화면)를 Claude Design에 넘겨 첫 화면을 받습니다.

💡 사용 환경

항목 값
운영체제 Windows
앱 Claude 데스크톱 앱
요금제 Pro
작업 폴더 C:\kiosk-project
있어야 하는 파일 Claude Work에서 쓴 기획서 kiosk-plan.md

강의 자료 받기

이 강의 자료는 세 개입니다. 파일 탐색기에서 C:\kiosk-project로 복사해 넣습니다.

  • haru-menu.md: 주문 화면에 넣을 메뉴 일곱 개, 가격, 옵션, 결제 방법입니다. 바닐라라테는 품절 표시를 해 보려고 품절로 적어 두었습니다.
  • cafe-logo-and-colors.md: 하루커피의 로고 설명, 색 값, 글꼴입니다.
  • reference-cafe-screen.md: 참고할 다른 카페의 주문 화면을 만든 사람이 쓴 실제 디자인 값 표입니다. Claude에게 올리지 않고, Claude가 화면에서 읽은 값을 맞춰 볼 때만 엽니다.

참고 화면의 캡처 reference-cafe-screen.png도 같은 폴더에 넣습니다. 이 캡처는 2단계에서 Claude에게 올립니다.

영상으로 먼저 보기

🎬 영상 바로 따라하는 웹사이트 디자인, 클로드 디자인 15분 가이드

영상이 웹사이트 하나를 만들며 첫 화면 요청, 참고 화면에서 모양 가져오기, 디자인 시스템 입히기, 직접 고치기의 차례를 어떻게 밟는지 보고 오면, 아래 단계가 어떤 모습으로 이어지는지 미리 알 수 있습니다.

영상의 둘째 단계는 터미널 도구(Dembrandt)로 참고 사이트의 실제 색과 글꼴 값을 뽑습니다. 이 강의는 터미널 명령을 입력하지 않으므로 그 도구를 쓰지 않고, 참고 화면의 화면 캡처를 올리는 방법으로 대신합니다. 영상의 마지막 단계인 발표 자료 만들기는 8강에서 합니다.

영상을 만든 사람은 전체 작업에 한 시간쯤 걸렸다고 말합니다. 다섯 단계를 한자리에서 이어 하려면 한 시간 남짓 비워 둡니다.

첫 화면 요청하기

→ 기획서와 메뉴 파일을 올려 주문 첫 화면을 한 줄로 요청하고, Claude가 되묻는 것에 답해 시안 하나를 고릅니다.

Claude Design 열기

Claude Design은 대화 입력창의 Output 메뉴에서 Design을 골라 엽니다. 사이드바의 Artifacts에서 Make something new를 눌러 Design을 골라도 같은 화면이 열립니다. Pro 요금제에서는 따로 켤 것이 없습니다.

따로 있던 Claude Design 화면(claude.ai/design)은 2026년 12월 14일에 닫힙니다. 닫힌 뒤에는 읽기만 되고 새 프로젝트를 만들 수 없습니다. 이 강의는 대화 입력창에서 여는 방법만 씁니다.

[화면 캡처: 1강-01 — 새 대화의 입력창에서 Output 메뉴를 펼친 화면. ① Output 메뉴, ② Design 항목] ▲ 입력창의 Output 메뉴에서 Design 고르기

① Claude 데스크톱 앱에서 새 대화를 엽니다.

② 입력창의 Output을 클릭합니다.

③ Design을 클릭합니다.

입력창 옆에 Design으로 바뀐 표시가 보이면 됩니다.

한 줄로 요청하기

기획서 kiosk-plan.md와 메뉴 파일 haru-menu.md를 올리고, 만들 화면을 한 줄로 요청합니다.

[화면 캡처: 1강-02 — Design 대화의 입력창에 파일 두 개를 올리고 요청문을 쓴 화면. ① 파일을 올리는 + 버튼, ② 올린 kiosk-plan.md와 haru-menu.md, ③ 보내기 버튼] ▲ 파일 두 개와 한 줄 요청을 담은 입력창

① 입력창의 + 버튼을 클릭합니다.

② C:\kiosk-project의 kiosk-plan.md와 haru-menu.md를 올립니다.

③ 아래 요청문을 입력창에 붙여 넣고 보내기 버튼을 클릭합니다.

올린 `kiosk-plan.md`와 `haru-menu.md`를 보고 카페 "하루커피"의 키오스크 주문 첫 화면(메뉴 선택 화면)을 만들어 줘.

Claude가 바로 그리지 않고 먼저 되물으면 됩니다.

되묻는 것에 답하기

[화면 캡처: 1강-03 — Claude가 되묻는 글이 보이는 Design 대화. ① 파일에서 읽은 내용, ② 되묻는 질문 목록] ▲ 화면을 그리기 전에 Claude가 되묻는 모습

Claude는 정보가 모자라면 그릴 화면의 배치를 정하기 전에 되묻습니다. 영상에서 Claude가 되물은 것은 디자인 시스템, 쓰는 사람, 목표, 넣을 부분, 말투, 시안 수 여섯 가지입니다. 여러분 화면에서 되묻는 것은 요청마다 달라질 수 있으니, 아래 표에서 되묻는 항목에 맞는 줄만 골라 답합니다.

Claude가 묻는 것 여기서 답할 값
디자인 시스템 아직 없습니다. 3단계에서 만듭니다.
쓰는 사람 kiosk-plan.md에 쓴 그대로입니다.
목표 kiosk-plan.md에 쓴 화면의 목표 그대로입니다.
넣을 부분 머리말, 분류 탭, 메뉴 카드, 장바구니입니다.
말투 짧고 친절한 존댓말입니다.
시안 수 세 개이고, 화면은 가로 1080, 세로 1920의 세로형 키오스크입니다.

쓰는 사람과 목표를 값으로 다시 쓰지 않고 기획서 그대로 쓰라고 하는 이유가 있습니다. 한 줄 요청에서 정해 준 것은 기획서와 메뉴 파일뿐이므로, Claude가 그린 화면이 기획서의 쓰는 사람과 목표에 맞는지 가릴 기준도 기획서뿐입니다.

① 되묻는 글에서 메뉴가 일곱 개이고 바닐라라테가 품절이라는 내용이 있으면 haru-menu.md와 같은지 봅니다.

② 아래 답을 입력창에 붙여 넣고 보냅니다.

디자인 시스템은 아직 없어. 쓰는 사람과 화면의 목표는 올린 `kiosk-plan.md`에 적은 그대로 써 줘. 화면에 꼭 넣을 부분은 머리말, 분류 탭, 메뉴 카드, 장바구니야. 문구는 짧고 친절한 존댓말로 써 줘. 세로형 키오스크 화면(가로 1080, 세로 1920)으로 시안 세 개를 보여 줘.

시안 고르고 부분 하나 더하기

[화면 캡처: 1강-04 — 시안 세 개가 나란히 보이는 Design 캔버스. ① 시안 1, ② 시안 2, ③ 시안 3] ▲ Claude가 그린 시안 세 개

시안 세 개가 나오면 배치를 비교합니다. 분류 탭의 위치, 한 화면에 보이는 메뉴 카드 수, 장바구니가 늘 보이는지가 시안마다 다릅니다. 기획서의 목표는 장바구니에서 옵션을 바로 고치는 것이므로, 장바구니가 눈에 들어오는 시안이 목표에 가깝습니다.

시안 하나를 고르고, 그 시안에 부분 하나만 더해 달라고 합니다. 부분 하나를 더해 달라고 하면 Claude는 나머지를 그대로 두고 그 부분만 더합니다. 아래 요청문은 두 번째 시안을 고른 경우이고, 다른 시안을 골랐으면 번호를 바꿉니다.

[화면 캡처: 1강-05 — 장바구니 막대를 더한 시안. ① 맨 아래 장바구니 막대의 담은 개수와 총액, ② 결제하기 버튼] ▲ 시안에 장바구니 막대만 더한 화면

① 아래 요청문을 입력창에 붙여 넣고 보냅니다.

두 번째 시안으로 할게. 다른 부분은 그대로 두고, 화면 맨 아래에 담은 개수와 총액, 결제하기 버튼이 늘 보이는 장바구니 막대만 더해 줘.

② 화면에서 아메리카노 Regular와 카페라테 Regular를 한 잔씩 담습니다.

③ 장바구니 막대의 총액을 haru-menu.md의 가격과 맞춰 봅니다.

막대에 담은 메뉴 2개와 8,300원이 보이면 됩니다. 아메리카노 Regular 3,800원과 카페라테 Regular 4,500원을 더한 값입니다. 화면에 보이는 숫자도 Claude가 쓴 글이므로, 가격은 haru-menu.md와 한 번씩 맞춰 봅니다. 바닐라라테 카드가 흐리게 보이고 품절 표시가 있는지도 함께 봅니다.

디자인 시스템 없이 만든 시안은 나쁘지 않지만 좋다고 느껴지지는 않습니다. 색은 회색과 검정뿐이고 간격과 버튼 크기는 Claude가 무난하게 고른 값이라, 배치는 기획서대로여도 하루커피의 화면이라는 느낌이 나지 않습니다.

참고 화면에서 모양 가져오기

→ 잘 만든 화면에서 가져올 요소와 가져오지 않을 요소를 정해 요청하고, Claude가 읽은 값을 표와 맞춰 봅니다.

베끼지 않고 다시 해석하기

[화면 캡처: 1강-06 — 참고할 다른 카페(파란돌 베이커리 카페)의 키오스크 주문 화면 캡처. ① 머리말, ② 세로 분류 탭, ③ 메뉴 카드 3열, ④ 품절 카드, ⑤ 맨 아래 장바구니 막대] ▲ 참고할 주문 화면: 머리말, 세로 분류 탭, 메뉴 카드, 품절 카드, 장바구니 막대

참고 화면을 보고 "이렇게 만들어 줘"라고 하면 그대로 베낀 화면이 나옵니다. 다른 가게의 로고와 색이 붙은 화면은 하루커피의 화면이 될 수 없고, 남의 디자인을 그대로 가져다 쓰는 일이기도 합니다. ==참고 화면은 베끼지 않고, 잘 만든 요소만 가져와 내 화면에 맞게 다시 해석합니다.==

가져올 것 가져오지 않을 것
간격 규칙 로고
카드 모양 가게 이름
늘 보이는 장바구니 막대 색
버튼 크기 메뉴 사진
품절 표시 방식  

색을 가져오지 않는 이유는 하루커피에 하루커피의 색이 따로 있기 때문입니다. 색은 3단계에서 cafe-logo-and-colors.md로 입힙니다.

캡처를 올려 요청하기

같은 Design 대화에 참고 화면 캡처를 올리고, 가져올 요소만 적어 요청합니다.

① 입력창의 + 버튼을 클릭합니다.

② reference-cafe-screen.png를 올립니다.

③ 아래 요청문을 입력창에 붙여 넣고 보냅니다.

올린 그림은 잘 만든 다른 카페의 주문 화면 캡처야. 이 화면을 베끼지 말고, 간격 규칙, 카드 모양, 늘 보이는 장바구니 막대, 버튼 크기, 품절 표시 방식만 가져와서 지금 시안을 하루커피에 맞게 다시 해석해 줘. 로고, 가게 이름, 색은 가져오지 마. 캡처에서 읽은 값은 px로 적어 줘.

[화면 캡처: 1강-07 — 참고 화면의 요소를 다시 해석한 주문 첫 화면. 카드 사이 간격, 카드 모서리, 장바구니 막대, 품절 카드가 보이게] ▲ 참고 화면의 요소를 하루커피에 맞게 다시 해석한 첫 화면

Claude의 답에 가져온 값이 px로 적혀 있고, 가져오지 않은 것(로고, 가게 이름, 색)이 따로 적혀 있으면 됩니다.

캡처에서 읽은 값은 Claude가 눈으로 짐작해 적은 값이라 정확하지 않을 수 있습니다. 장바구니 막대가 맨 아래에 있고 품절 카드가 흐리다는 배치와 모양은 화면에 드러나 맞게 읽기 쉽습니다. 반대로 모서리가 12px인지 10px인지, 버튼 높이가 64px인지 60px인지는 그림에 숫자로 적혀 있지 않습니다. 숫자로 된 값은 reference-cafe-screen.md의 표와 맞춰 보고 씁니다.

항목 reference-cafe-screen.md의 값
간격 8px의 배수(8, 16, 24, 32)
카드 모서리 12px
카드 그림자 검정 8%, 아래로 2px
누르는 버튼 높이 64px 이상
결제하기 버튼 폭 360px, 글자 36px
장바구니 막대 높이 160px

① Claude가 적은 값을 위 표의 값과 하나씩 맞춰 봅니다.

② 다른 값이 있으면 아래 요청문의 해당 줄만 남겨 보냅니다.

네가 읽은 값 가운데 아래와 다른 것을 이 값으로 고쳐 줘. 카드 모서리 12px, 카드 그림자 검정 8%에 아래로 2px, 누르는 버튼 높이 64px 이상, 결제하기 버튼 폭 360px에 글자 36px, 장바구니 막대 높이 160px.

값이 모두 표와 같으면 보내지 않고 다음으로 넘어갑니다. 값을 정확히 알 수 있는 표가 없는 화면을 참고할 때는 Claude가 읽은 값을 정답이 아니라 출발점으로 보고, 화면을 보며 다듬어 갑니다.

디자인 시스템이란

[이미지: 1강-08 — 기술 그림.] ▲ 디자인 시스템 하나가 주문 화면, 발표 자료, 시제품에 같은 모양을 입히는 흐름

디자인 시스템은 화면을 만들 때 지킬 모양의 규칙을 모아 둔 묶음입니다. 어떤 색을 어디에 쓰는지, 제목과 본문은 어떤 글꼴로 쓰는지, 간격은 몇 px 단위인지, 버튼과 카드는 어떻게 생겼는지가 들어 있습니다. 매번 "버튼은 갈색으로, 모서리는 12px로"라고 되풀이하지 않고 디자인 시스템 하나를 골라 주면, Claude가 그 규칙으로 화면을 그립니다.

  • 만드는 재료: 코드, 발표 자료와 문서, 로고, 색 견본, 글꼴 견본, 시제품 화면 캡처, Figma 파일입니다.
  • 요금제: Pro에서는 beta이고 기본으로 켜져 있습니다.
  • 쓰는 방법: 만들면 아티팩트가 되어 어느 대화에서나 고를 수 있습니다. 새 대화의 입력창에서 + 버튼 > Design system을 고릅니다.

고치는 세 방법

Claude Design에서 고치는 방법은 대화만이 아니라 셋입니다.

방법 맞는 때 고치는 법
대화(Using chat) 배치 전체를 바꾸거나 여러 부분에 같은 규칙을 적용하는 큰 변경 입력창에 요청을 써서 보냅니다.
inline comments 한 부분만 짚어 Claude의 판단으로 고치고 싶을 때 comments를 켜고 고칠 요소를 눌러 쓴 뒤 Send to Claude를 켠 채 올립니다.
캔버스에서 직접 고치기(Edit directly on the canvas) Claude의 판단이 필요 없는 작은 손질 요소를 끌어 옮기고 크기를 바꾸고, 글자는 두 번 눌러 고쳐 씁니다.

Properties는 고른 요소의 설정을 보여 줍니다. 캔버스에서 바꾼 것은 저절로 저장됩니다. 지금까지 한 요청은 모두 대화로 한 것입니다. 지금 화면과 다른 방향을 시험해 보고 싶으면 제목 메뉴의 Duplicate로 디자인을 복제해 거기서 시험합니다.

세 방법을 고르는 기준은 고칠 부분이 하나인지 여러 개인지, Claude의 판단이 필요한지입니다. 글자 몇 개를 바꾸는 일은 판단이 필요 없어 캔버스에서 직접 고치는 편이 손이 덜 갑니다. 버튼 하나를 고치되 어떻게 고칠지 Claude의 판단을 듣고 싶으면 comment로 시킵니다.

[화면 캡처: 1강-11 — 캔버스에서 머리말 안내 문구를 고른 Design 화면. ① 머리말의 안내 문구, ② Properties, ③ comment를 쓰는 입력 칸과 Send to Claude] ▲ 캔버스에서 요소를 고른 화면

① comments를 켭니다.

② 결제하기 버튼을 클릭합니다.

③ comment 입력 칸에 결제하기 버튼을 더 크게 해 줘를 씁니다.

④ Send to Claude를 켠 채 comment를 올립니다.

Claude가 결제하기 버튼만 고치고 comment에 답하면 됩니다. comment가 반영되지 않으면 같은 내용을 대화에 붙여 넣어 보냅니다.

고친 모양 남기기

→ 고친 모양이 디자인 시스템에 저절로 따라가는지 확인하고, 다음 강의에서 쓸 디자인 시스템을 남깁니다.

고친 모양이 따라가지 않는 이유

디자인 시스템은 화면을 그릴 때 Claude가 읽는 규칙이고, 화면을 고친다고 그 규칙이 바뀌지는 않습니다. 앞 단계에서 한국어 줄바꿈이나 버튼 글자를 고친 것은 지금 화면에만 적용된 것입니다. 캔버스에서 손으로 고친 것도 코드에 되쓰이지 않고 저장만 됩니다. 고친 모양을 다음 결과물에도 쓰려면 디자인 시스템에 넣어 달라고 따로 요청해야 합니다.

공식 안내에 직접 고친 디자인을 기존 디자인 시스템에 반영하는 방법은 없습니다. 영상에서도 반영하라고 하자 되지 않아 새 디자인 시스템을 만들었습니다. 그래서 반영을 먼저 요청하고, 되지 않으면 새로 만들게 합니다.

디자인 시스템에 반영 요청하기

① 아래 요청문을 입력창에 붙여 넣고 보냅니다.

지금 화면의 고친 모양을 디자인 시스템에 남겨 줘. 남길 것은 한국어 줄바꿈과 가격 표기 규칙, 다듬은 문구와 버튼 글자, 결제하기 버튼의 모양이야. 기존 디자인 시스템 "하루커피"에 반영할 수 있으면 반영하고, 반영할 수 없으면 지금 화면을 바탕으로 새 디자인 시스템 "하루커피 키오스크"를 만들어 줘. 무엇이 들어갔고 무엇이 들어가지 못했는지 알려 줘.

② 답에서 들어간 것과 들어가지 못한 것을 읽습니다.

캔버스에서 직접 고친 글자는 Claude에게 전해지지 않아 들어가지 못했다고 답할 수 있습니다. 그러면 바꾼 내용을 말로 적어 보냅니다.

캔버스에서 머리말 안내 문구를 "주문할 메뉴를 골라 주세요"로 바꿨어. 이것도 디자인 시스템에 넣어 줘.

다음 강의에서 쓸 이름 정하기

사용 한도 알아 두기

Design의 모든 작업은 평소 대화와 같은 요금제의 사용 한도를 씁니다. 디자인용으로 따로 주어지는 양이 없으므로 시안을 여러 번 다시 그리게 하거나 고치는 횟수가 많을수록 한도를 더 씁니다. 같은 일을 두 번 시키지 않도록 고칠 것을 모아 한 번에 요청하는 편이 좋습니다.

Claude가 되묻지 않고 바로 시안을 그립니다. 그린 시안으로 이어 가면 됩니다. 쓰는 사람과 목표가 기획서와 다르게 쓰였으면 kiosk-plan.md에 적은 그대로 쓰라고 요청합니다.

참고 화면에서 읽은 값이 reference-cafe-screen.md의 표와 다릅니다. 다른 값만 골라 표의 값으로 고쳐 달라고 요청합니다.
디자인 시스템을 입혔는데 글자가 다른 글꼴로 보입니다. 글꼴 이름이 디자인 시스템에 적혀 있는지 확인하고, 바꾼 글꼴로 화면 전체를 맞추라고 요청합니다.
한국어 다듬기 Skill을 썼다고 하지 않습니다. 요청문의 기준만으로 다듬은 결과입니다. 답에 적힌 기준을 읽고 쓸지 정합니다.
comment를 올렸는데 화면이 바뀌지 않습니다. 같은 내용을 대화에 붙여 넣어 보냅니다.
반영 요청에 디자인 시스템이 새로 만들어집니다. 새로 만든 디자인 시스템 이름을 하루커피 키오스크로 바꿔 달라고 요청합니다.
Design system 목록에 만든 디자인 시스템이 보이지 않습니다. 새 대화를 다시 열어 확인하고, 그래도 없으면 Design 대화에서 디자인 시스템이 만들어졌는지 Claude에게 묻습니다.

정리

→ 이 강의에서 만든 것과 알아본 것을 모으고, 다음 강의로 잇습니다.

이 강의에서 기획서와 메뉴 파일로 주문 첫 화면을 받고, 참고 화면에서 모양만 가져와 디자인 시스템을 만들어 입혔습니다. 문구를 다듬고 고친 모양을 디자인 시스템에 남겼습니다.

  • 되묻는 것에 답하기: 한 줄 요청은 Claude가 되묻는 것에 답해 가며 구체화합니다. 쓰는 사람과 목표는 기획서에서 가져옵니다.
  • 다시 해석하기: 참고 화면은 베끼지 않고 요소만 가져옵니다. 캡처에서 읽은 숫자는 짐작이므로 표와 맞춰 봅니다.
  • 디자인 시스템: 색, 글꼴, 간격, 부품의 규칙을 모아 두어 같은 모양을 매번 설명하지 않게 합니다.
  • 고치는 세 방법: 큰 변경은 대화, 한 부분은 comment, 작은 손질은 캔버스에서 직접 고칩니다.
  • 고친 모양 남기기: 화면을 고쳐도 디자인 시스템은 바뀌지 않으므로 따로 요청해 남깁니다.

✔ 정리 디자인 시스템 하루커피 키오스크에 고친 모양을 남기고, Design에 주문 첫 화면을 만들었습니다.

❓ 질문 하루커피의 모양을 입힌 첫 화면을 3초만 보면, 무엇이 가장 먼저 눈에 들어와야 할까요?
