이전 강의 자료(티스토리)

키오스크 기능 가르기와 사람이 확인할 곳

이 파일은 4강에서 웹 서비스의 부분을 키오스크에 짝 짓고, 키오스크 기능을 프론트엔드만으로 되는 것과 아닌 것으로 가를 때 쓰는 활동지입니다. 답은 맨 아래 "답" 장에 있으니 먼저 가린 뒤 풉니다.

1. 가게를 여는 여덟 단계와 키오스크

빈칸에 키오스크에서 그 일을 하는 부분을 적습니다.

단계 가게에 비유하면 키오스크에서는
프론트엔드 손님이 보는 매장  
HTML, CSS, JavaScript, React 매장의 구조, 인테리어, 움직이는 장치, 조립 도구  
백엔드 주방  
데이터베이스 장부  
API 주문서, 밖에서 빌려 오는 기능  
서버와 클라우드 가게 공간과 빌려 쓰는 방식  
배포와 도메인 개업과 간판  
결제, 로그인, API 키 금고와 열쇠, 사람이 꼭 확인할 곳  

2. 기능 가르기

아래 기능마다 프론트엔드만으로 되는지(화면만 있으면 되는지), 백엔드나 데이터베이스가 필요한지 고릅니다.

기능 프론트엔드만 / 백엔드 필요
1. 하루커피 소개와 메뉴판을 보여 주는 페이지  
2. 옵션을 고르면 화면의 금액이 바뀐다  
3. 손님이 낸 주문을 주방 화면에 보낸다  
4. 오늘 팔린 잔 수를 매일 모아 본다  
5. 카드로 실제 결제한다  
6. 품절을 직원이 바꾸면 모든 키오스크에 바로 보인다  
7. 3강에서 만든 클릭되는 시제품을 다른 사람이 눌러 본다  
8. 회원 적립 포인트를 쌓는다  

3. 빠진 확인 찾기

아래는 어떤 팀이 "확인 다 했다"고 적은 메모입니다. 영상이 말한 사람이 확인할 곳 셋 가운데 빠진 것을 찾습니다.

결제사 API 키는 화면 코드에 넣지 않고 서버에만 두었다. 주문 기록은 로그인한 직원만 볼 수 있게 막았다. 금액은 손님 화면에서 계산한 값을 그대로 결제사에 보낸다.

답

1장: 프론트엔드는 메뉴 화면, 장바구니, 결제 방식 화면입니다. HTML은 화면의 칸, CSS는 색과 글꼴, JavaScript는 옵션을 고르면 금액이 바뀌는 동작입니다. 백엔드는 주문을 받아 처리하는 곳, 데이터베이스는 주문 기록과 메뉴, 품절 정보입니다. API는 결제사와 주방 화면에 주문을 넘기는 연결입니다. 서버와 클라우드는 백엔드가 돌아가는 빌린 컴퓨터, 배포와 도메인은 손님이 여는 주소입니다. 결제, 로그인, API 키는 카드 결제, 직원 로그인, 결제사 키입니다.

2장: 1, 2, 7은 프론트엔드만으로 됩니다. 3, 4, 5, 6, 8은 주문이나 기록을 저장하고 여러 곳에 나눠 주어야 하므로 백엔드나 데이터베이스가 필요합니다.

3장: 결제 금액을 서버에서 다시 확인하지 않았습니다. 손님 화면에서 계산한 값은 바꿔치기할 수 있으므로, 서버가 메뉴와 옵션으로 금액을 다시 계산해 확인해야 합니다.
