받은 답은 내가 읽고, 확인하고, 필요하면 내 손으로 파일에 옮겼습니다.

폴더 목록을 만드는 요청문

폴더가 연결되었으면 아래 요청문을 입력창에 그대로 붙여 넣고 보냅니다.

연결한 `C:\kiosk-project` 폴더에 있는 파일을 모두 살펴보고, 파일마다 무엇이 든 파일인지 한 줄로 설명한 목록을 만들어 줘. 목록은 파일 이름, 파일 종류, 한 줄 설명의 세 칸으로 된 표로 쓰고, 같은 폴더에 `folder-index.md`라는 이름으로 저장해 줘. 파일을 열어 보지 못해 내용을 모르는 파일은 짐작해 채우지 말고 설명 칸에 "열어 보지 못함"이라고 적어 줘. 이 폴더 밖의 파일은 읽지 말고, 지금 있는 파일은 고치거나 지우지 마.

요청문에는 네 가지를 적었습니다.
무엇을 만들지(세 칸짜리 표), 어디에 어떤 이름으로 저장할지(folder-index.md), 모르는 것은 어떻게 할지("열어 보지 못함"), 하지 말 일(폴더 밖 읽기, 있는 파일 고치기와 지우기)입니다.

Auto와 Manual

folder-index.md를 저장하기 전에 Claude가 저장해도 되는지 묻는 창은 뜨지 않았습니다.

⚠ 확인 필요 Auto에서 새 파일을 저장할 때 묻는 창이 뜨지 않는지

⚠ 확인 필요 입력창에서 승인 설정이 놓인 자리와 모양

고를 수 있는 것은 둘입니다.

  • Auto는 Claude가 단계마다 멈추지 않고 일하는 방식입니다.

  • Manual은 Claude가 행동하기 전에 여러분에게 묻는 방식입니다.
    Claude가 무엇을 하려는지 창으로 보여 주고, 여러분이 창마다 Allow(허락)나 Deny(거절)를 고릅니다.

두 방식에 같은 것도 있습니다.

그리고 어느 방식에서든 Claude는 파일을 영구히 지우기 전에 반드시 묻고, 여러분이 Allow를 골라야 지웁니다.

두 방식이 묻는 일

[이미지: 1강-4.2-1 — 기술 그림.] ▲ Auto와 Manual이 일마다 묻는 자리의 차이

지금 이 대화는 Auto입니다.
새 파일 쓰기와 이름 바꾸기는 묻지 않고, 영구히 지우기만 묻습니다.
Claude가 파일을 바꾸기 전에 늘 묻는 것이 아니라는 것은 Pro의 처음 설정이 Auto이고, 앞의 일에서 아무 창 없이 folder-index.md가 생겼다는 데서 알 수 있습니다.
지우기는 어느 방식에서도 묻습니다.

일 여섯의 위험 가르기

무엇을 Auto로 맡기고 무엇을 Manual로 맡길지는 일마다 위험이 얼마나 큰지로 정합니다.
위험은 두 가지로 가릅니다.
잘못되었을 때 되돌릴 수 있는가, 그리고 결과가 내 폴더 밖의 사람이나 돈에 닿는가입니다.

아래 여섯 일이 키오스크 프로젝트에서 맡길 만한 일의 예입니다.

1. 폴더의 파일을 읽고 요약하기
2. 폴더에 새 파일 쓰기
3. 폴더의 파일 이름 바꾸기
4. 폴더의 파일 지우기
5. 카페 사장님께 메일 보내기
6. 키오스크 부품을 온라인에서 결제하기

이 두 질문으로 여섯을 가르면 이렇습니다.

  • 요약하기는 파일을 바꾸지 않으므로 위험이 가장 낮습니다.
    공식 안전 수칙도 예약 작업을 자동으로 돌릴 때 처음에는 요약이나 자료 모으기처럼 위험이 낮은 일부터 맡기라고 권합니다.
  • 새 파일 쓰기도 낮습니다.
    있던 파일을 건드리지 않으므로 마음에 들지 않으면 새 파일만 지우면 됩니다.
  • 파일 이름 바꾸기는 중간입니다.
    되돌릴 수는 있지만 원래 이름을 알아야 되돌릴 수 있습니다.
    원래 이름을 적어 두지 않았다면 다섯 파일이 무엇이었는지 다시 찾아야 합니다.
  • 파일 지우기는 높습니다.
    영구히 지운 파일은 되돌릴 수 없고, 그래서 어느 승인 방식에서도 Claude가 묻습니다.
  • 메일 보내기와 결제는 가장 높습니다.
    보낸 메일은 거둘 수 없고 받는 사람에게 닿으며, 결제는 돈이 나갑니다.
    공식 안전 수칙은 메시지 보내기와 구매를 되돌리기 어려운 일의 예로 들고, 이런 일에는 Manual로 바꾸라고 권합니다.
위험 일 이유
낮음 1 요약하기, 2 새 파일 쓰기 있던 파일을 바꾸지 않는다
중간 3 이름 바꾸기 원래 이름을 남겨 두면 되돌릴 수 있다
높음 4 지우기, 5 메일 보내기, 6 결제 되돌릴 수 없거나, 남에게 닿거나, 돈이 나간다

이름 정리 요청문 직접 쓰기

이번에는 요청문을 여러분이 직접 씁니다.
처음 요청문에서 본 네 가지(무엇을 할지, 결과를 어떻게 남길지, 모를 때 어떻게 할지, 하지 말 일)를 넣고, 아래 조건이 모두 들어가게 메모장에 요청문을 씁니다.

  • C:\kiosk-project\notes-inbox의 메모 파일 다섯의 이름을 정리한다.
  • 새 이름은 영어 소문자와 하이픈으로만 짓고, 파일을 열어 내용이 드러나는 낱말을 쓴다.

  • 파일 내용은 고치지 않고, 지우거나 옮기지 않는다.

바꿀 이름의 목록 읽기

보내면 Claude는 먼저 다섯 파일을 열어 읽고, 바꿀 이름의 목록을 보여 줍니다.
아래는 Claude가 실제로 낸 목록과 이유입니다.

다섯 파일을 모두 열어 내용을 읽었습니다. 바꿀 이름은 다음과 같습니다.

1. `Kiosk 화면 메모.TXT` → `kiosk-screen-notes.txt`
2. `새 텍스트 문서.txt` → `2026-10-20-team-meeting-notes.txt`
3. `설문문항 초안(최종)(2).txt` → `customer-survey-questions-draft.txt`
4. `인터뷰질문_v3_진짜최종.txt` → `owner-interview-questions.txt`
5. `카페방문메모 1018.txt` → `2026-10-18-haru-coffee-visit-notes.txt`

이름을 지은 근거와 확인하실 것은 이렇습니다.

- 날짜는 파일 안에 적힌 날짜만 썼습니다. `새 텍스트 문서.txt`는 첫 줄이 "10월 20일 팀 회의 메모"이고, `카페방문메모 1018.txt`는 첫 줄이 "10월 18일 하루커피 방문 메모"입니다. 두 파일 모두 연도는 적혀 있지 않아, 요청에 예로 드신 `2026-`을 따라 2026년으로 붙였습니다. 연도가 다르면 알려 주세요.
- `새 텍스트 문서.txt` 안의 "10월 27일"은 다음 회의 날짜라서 이름에 쓰지 않았습니다.
- 나머지 세 파일에는 날짜가 없어 날짜를 붙이지 않았습니다.
- `(최종)(2)`, `v3_진짜최종` 같은 판 표시는 내용이 아니라서 새 이름에서 뺐습니다. 어느 것이 최종판인지 이름으로 남겨야 하면 `-v3`처럼 붙이겠습니다.

AI와 일하는 능력의 네 가지

마지막으로 오늘 한 일을 하나의 틀로 묶습니다.
Anthropic Academy의 AI Fluency 과정은 AI와 일하는 능력을 네 가지로 나눠 가르칩니다.
이 강의에서는 네 가지를 우리말로 맡기기, 설명하기, 가려내기, 책임지기라고 부릅니다.

[이미지: 1강-9.1-1 — 기술 그림.] ▲ 맡기기, 설명하기, 가려내기, 책임지기의 네 가지 틀

  • 맡기기(Delegation)는 무엇을 AI에게 맡기고 무엇을 내가 할지 정하는 일입니다.
  • 설명하기(Description)는 원하는 결과물과 일하는 방식을 AI가 알아듣게 전하는 일입니다.
  • 가려내기(Discernment)는 AI가 낸 결과와 AI가 일한 과정을 비판적으로 살펴보는 일입니다.
  • 책임지기(Diligence)는 AI와 함께 만든 결과에 대해 사람이 책임을 지는 일입니다.

과정은 책임지기를 만들 때, AI를 썼다고 밝힐 때, 결과를 내보낼 때의 셋으로 나눠 다룹니다.

오늘 맡긴 일 셋을 네 가지로 나누기

오늘 Claude에게 맡긴 일 셋(폴더 목록, 파일 이름 정리, 웹 글 요약)을 네 가지로 나누면 이렇습니다.

  • 맡기기: 폴더 목록 만들기와 파일 이름 정리처럼 되돌릴 수 있는 일만 맡겼고, 파일 지우기와 결제는 맡기지 않았습니다.
    웹 글 요약은 파일을 바꾸지 않지만 숨은 지시가 든 바깥 글을 읽게 하는 일이라 Manual에서 맡겼습니다.
  • 설명하기: 요청에 저장할 파일 이름, 표의 칸, 모르는 파일은 "열어 보지 못함"으로 적는 것, 이름 규칙, 바꾸기 전에 목록을 먼저 보여 달라는 것, 요약에 글에 없는 내용을 더하지 말라는 것, 하지 말 일을 적었습니다.
  • 가려내기: 폴더에서 결과 파일을 직접 열어 보았고, 승인 창마다 어느 파일을 어떻게 바꾸는지 읽고 Allow나 Deny를 골랐습니다.
    요약은 브라우저 화면과 메모장으로 연 원본을 함께 보며 숨은 지시를 따랐는지, 글에 없는 내용이 더해졌는지 대조했습니다.
  • 책임지기: 폴더를 미리 백업했고, 결과를 쓸지 정하는 사람은 나입니다.
    출처를 확인해야 할 문장은 실제 자료와 대조하고, 오늘 한 일과 대조한 결과는 ai-log.md에 적습니다.
