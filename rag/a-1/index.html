1강. Code 설치하고 열기

환경 설정 강의 ⏱ 40분

학습 목표

  • Claude Code 사용 조건(요금제, Windows 버전) 확인
  • 설치 방법 세 가지의 차이 알기
  • PowerShell 한 줄로 설치하고 claude --version으로 확인
  • 로그인하고 VS Code에서 첫 요청 보내기
  • 터미널 claude와 VS Code 확장의 차이 알기

준비

→ 내 계정과 PC가 Claude Code를 쓸 수 있는 조건인지 확인합니다.

💡 사용 환경

항목 값
운영체제 Windows 11
요금제 Claude Pro 이상
편집기 VS Code
터미널 PowerShell

요금제

Claude Code는 Pro, Max, Ultra, Team, Enterprise 요금제나 Console 계정(API 사용량으로 결제하는 개발자용 계정)이 있어야 씁니다. 무료 claude.ai 요금제에는 Claude Code가 포함되지 않습니다.

claude.ai에 로그인해 계정 설정에서 현재 요금제를 확인합니다. 무료 요금제라면 Pro 이상으로 올린 뒤 이어 갑니다.

Windows 버전과 WSL

Claude Code는 Windows 10 1809 이상이나 Windows Server 2019 이상에서 씁니다. Windows 11이면 이 조건을 충족합니다.

WSL(Windows 안에서 리눅스를 쓰게 해 주는 기능)은 필요 없습니다. 여기서는 WSL 없이 Windows에 직접 설치합니다.

💡 참고 Windows에 직접 설치하면 샌드박스(Claude Code가 실행하는 명령의 접근 범위를 제한하는 기능)를 쓸 수 없습니다. 샌드박스는 WSL 2에서만 지원됩니다. 여기서는 2강에서 배울 승인 화면으로 명령을 직접 확인하며 진행합니다.

Windows 11과 Pro 이상 요금제(또는 Console 계정)가 있으면 바로 설치할 수 있습니다.

↓ 이어서 설치 방법에는 어떤 것이 있고, 그중 무엇을 골라야 할까요?

설치 방법 고르기

→ 설치 방법 세 가지의 차이를 알고 여기서 쓸 방법을 고릅니다.

세 방법 비교

방법 설치 명령 필요한 것 업데이트
PowerShell 아래에서 실행하는 한 줄 없음. 관리자 권한도 필요 없습니다 자동
WinGet winget install Anthropic.ClaudeCode WinGet 직접
npm npm install -g @anthropic-ai/claude-code Node.js 22 이상 -

PowerShell 방법은 Windows에 직접 설치하는 네이티브 설치입니다. npm은 win32-x64와 win32-arm64를 지원합니다. 표에서 업데이트 칸이 빈 npm은 여기서 쓰지 않으므로 업데이트 방식을 다루지 않습니다.

업데이트 방식

네이티브 설치는 백그라운드에서 자동으로 업데이트됩니다. 어느 릴리스 채널로 받을지는 autoUpdatesChannel 설정에서 latest나 stable 중에 고릅니다.

WinGet 설치는 자동으로 업데이트되지 않습니다. 새 버전을 받으려면 아래 명령을 직접 실행해야 합니다.

winget upgrade Anthropic.ClaudeCode

여기서는 PowerShell 설치를 씁니다. 관리자 권한도 Node.js도 필요 없고, 업데이트를 직접 챙기지 않아도 되기 때문입니다.

↓ 이어서 PowerShell에서는 어떤 명령을 실행해야 설치될까요?

PowerShell로 설치하기

→ PowerShell 창에서 한 줄 명령으로 Claude Code를 설치합니다.

설치 명령 실행

① Windows 키를 누릅니다.

② PowerShell을 입력하고 Enter 키를 누릅니다.

PowerShell 창이 열리면 아래 명령을 실행합니다. 관리자 권한으로 열지 않아도 됩니다.

irm https://claude.ai/install.ps1 | iex

[화면 캡처: 1강-01 — 설치 명령 실행. PowerShell 창에 설치 명령을 붙여 넣은 화면. ① 명령을 입력하는 줄] ▲ PowerShell에서 설치 명령 실행

① 위 명령을 붙여 넣고 Enter 키를 누릅니다.

설치가 진행된 뒤 오류 문구 없이 입력하는 줄이 다시 나타나면 끝난 것입니다.

명령 프롬프트에서 설치할 때

명령 프롬프트(CMD)에서는 설치 명령이 다릅니다. irm은 CMD에서 인식되지 않고, 아래 명령에 있는 &&는 PowerShell에서 구분자로 인식되지 않기 때문입니다. 입력하는 줄이 PS C:\...>로 시작하면 PowerShell이고, C:\...>로 시작하면 CMD입니다.

curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

Git for Windows

Git for Windows는 선택 사항입니다. 설치하면 Claude Code의 Bash 도구와 Monitor 도구가 쓰는 Git Bash가 생기지만, 없어도 Claude Code는 설치됩니다.

설치는 셸에 맞는 명령 한 줄이면 끝납니다. 여기서는 PowerShell 명령을 씁니다.

↓ 이어서 설치가 제대로 됐는지는 어떻게 확인하고, 로그인은 어떻게 할까요?

설치 확인과 로그인

→ 설치를 확인하고 Claude 계정으로 로그인합니다.

설치 확인

PowerShell에서 아래 명령을 실행합니다.

claude --version

[화면 캡처: 1강-02 — 설치 확인. PowerShell 창에서 claude --version을 실행한 결과. ① 버전 번호가 나온 줄 (Claude가 찍을 수 있음)] ▲ 설치 확인 결과

① 버전 번호가 출력됐는지 봅니다.

'claude' is not recognized가 나오면 PowerShell을 닫고 새로 연 뒤 다시 실행합니다. 그래도 같으면 아래 막혔을 때의 첫 증상을 따릅니다.

설정까지 점검하려면 아래 명령을 실행합니다. 점검 결과가 화면에 나옵니다.

claude doctor

로그인

연습용 빈 폴더를 만들고 그 폴더에서 claude를 실행합니다. 아무 파일이 없는 폴더에서 시작하면 Claude Code가 읽을 수 있는 파일이 없습니다.

mkdir $HOME\claude-first
cd $HOME\claude-first
claude

[화면 캡처: 1강-03 — 로그인. claude를 처음 실행했을 때 나오는 로그인 안내 화면. ① 로그인 안내 문구] ▲ 처음 실행할 때 나오는 로그인 안내

① 안내 문구에 따라 브라우저에서 Claude 계정으로 로그인합니다.

② 로그인이 끝나면 PowerShell로 돌아와 입력창이 보이는지 봅니다.

③ /exit를 입력하고 Enter 키를 눌러 나옵니다.

claude --version이 버전 번호를 보여 주고 로그인까지 끝났으면 설치는 완료입니다.

↓ 이어서 이제 VS Code에서는 어떻게 Claude Code를 열고 첫 요청을 보낼까요?

VS Code에서 열기

→ VS Code에 확장을 설치하고 연습 폴더에서 첫 요청을 보냅니다.

확장 설치

VS Code가 없으면 code.visualstudio.com에서 받아 설치한 뒤 시작합니다. 이 확장을 설치해도 터미널에서 쓰는 claude는 생기지 않으므로, 앞에서 한 PowerShell 설치가 따로 필요합니다.

① Ctrl 키와 Shift 키와 X 키를 함께 누릅니다.

[화면 캡처: 1강-04 — 확장 설치. VS Code의 Extensions 화면에서 Claude Code를 검색한 결과. ① 검색 칸, ② 게시자가 Anthropic인 Claude Code의 Install 버튼] ▲ Claude Code 확장 설치

① 검색 칸에 Claude Code를 입력합니다.

② 게시자가 Anthropic인 Claude Code의 Install 버튼을 클릭합니다.

폴더 열고 Claude Code 열기

VS Code 메뉴에서 File > Open Folder를 클릭하고 앞에서 만든 claude-first 폴더(C:\Users\<내 이름>\claude-first)를 고릅니다.

Claude Code 패널을 여는 방법은 네 가지입니다.

방법 위치
편집기 오른쪽 위 Spark 아이콘 편집기 오른쪽 위
Activity Bar의 Spark 아이콘 왼쪽 세로 막대
상태 표시줄의 Claude Code 아래쪽 막대
명령 팔레트(Command Palette)의 Claude Code 명령 Ctrl 키와 Shift 키와 P 키

명령 팔레트에는 Open in Side Bar, Open in New Tab, Open in New Window, Open in Terminal이 있습니다. 여기서는 Activity Bar의 Spark 아이콘을 씁니다.

[화면 캡처: 1강-05 — 패널 열기. claude-first 폴더를 연 VS Code 화면. ① Activity Bar의 Spark 아이콘] ▲ Claude Code 패널을 여는 아이콘

① Activity Bar의 Spark 아이콘을 클릭합니다.

처음 열 때 로그인 안내가 나오면 터미널에서 로그인한 계정으로 로그인합니다.

첫 요청 보내기

[화면 캡처: 1강-06 — 첫 요청. Claude Code 패널의 입력창. ① 입력창] ▲ 첫 요청을 보내는 입력창

① 입력창에 아래 요청을 붙여 넣고 Enter 키를 누릅니다.

지금 열린 폴더에 어떤 파일이 있는지 알려 줘. 파일은 고치지 마.

폴더에 있는 파일을 알려 주는 답이 오면 첫 세션이 열린 것입니다. 연습 폴더는 비어 있으므로 비어 있다는 답이 와도 맞습니다.

💡 팁 입력창 아래 mode 표시기에서는 Claude Code가 파일을 고치기 전에 묻는 방식(mode)을 Auto, Manual, Plan, Edit automatically 가운데 고릅니다. 이번 요청은 파일을 읽기만 하므로 어느 mode에서도 폴더가 바뀌지 않습니다. 묻는 방식은 2강에서 배웁니다.

VS Code의 입력창에서 요청을 보내 답을 받으면 첫 세션이 열린 것입니다.

↓ 이어서 방금 쓴 확장과 PowerShell에서 설치한 claude는 같은 Claude Code인데, 무엇이 같고 무엇이 다를까요?

터미널과 확장의 차이

→ 터미널의 claude와 VS Code 확장이 어떻게 설치되고 무엇이 다른지 알아봅니다.

설치는 따로, 기록은 함께

[이미지: 1강-07 — 기술 그림.] ▲ 따로 설치되고 기록을 함께 쓰는 터미널과 확장

확장은 채팅 패널에 쓸 Claude Code 사본을 확장 안에 넣고, 그 사본을 PATH(명령 이름으로 프로그램을 찾는 경로 목록)에 등록하지 않습니다. 그래서 터미널에서 claude를 쓰려면 PowerShell 설치가 따로 필요했습니다.

설치가 따로여도 둘은 대화 기록, 설정 파일(settings.json), MCP 서버(Claude Code에 외부 도구를 잇는 서버), 플러그인을 함께 씁니다.

터미널과 확장에서 다른 기능

항목 터미널 claude VS Code 확장
! Bash 단축키 있습니다 없습니다
Tab 자동완성 있습니다 없습니다
파일 수정 승인 터미널의 승인 화면에서 고릅니다 Manual mode에서 나란히 보는 diff를 보고 Accept나 Reject를 고릅니다

확장에만 있거나 다른 점은 둘입니다.

  • 명령과 skill: 일부만 쓸 수 있습니다. 입력창에 /를 쳐서 목록을 확인합니다.
  • plan mode: 계획을 Markdown 문서로 열어 시작하기 전에 댓글을 달 수 있습니다. 입력창에서 /plan을 쓰려면 버전 2.1.280 이상이어야 합니다.

터미널과 확장 오가기

확장에서 만든 대화는 터미널에서도 이어 갈 수 있습니다. PowerShell에서 아래 명령을 실행합니다.

cd $HOME\claude-first
claude --resume

목록에 방금 확장에서 보낸 첫 요청이 보이면 됩니다. 확인했으면 Ctrl 키와 C 키를 함께 눌러 나옵니다.

반대로 확장 안에서 터미널을 쓰려면 명령 팔레트의 Open in Terminal을 실행합니다. 확장 화면으로 돌아오려면 설정 claudeCode.useTerminal을 끕니다.

터미널의 claude와 확장은 따로 설치된 두 입구이고, 대화 기록과 설정은 함께 씁니다. 2강부터는 !와 Tab 자동완성이 있는 터미널의 claude로 진행합니다.

↓ 이어서 설치하다가 막히면 어떻게 해야 할까요?

막혔을 때

→ 설치와 로그인, VS Code에서 자주 막히는 증상과 해결 방법입니다.

증상 해결
'claude' is not recognized 오류가 난다 설치 폴더 %USERPROFILE%\.local\bin이 PATH에 없는 것입니다. 시작 메뉴에서 환경 변수를 검색해 열고 사용자 변수 Path에 이 폴더를 추가한 뒤 PowerShell을 새로 엽니다
명령 프롬프트에서 irm이 인식되지 않는다 irm은 PowerShell 명령입니다. PowerShell을 열어 실행하거나 CMD용 명령을 씁니다
PowerShell에서 CMD용 명령의 &&가 오류를 낸다 &&는 PowerShell에서 구분자로 인식되지 않습니다. PowerShell용 한 줄 명령을 씁니다
npm으로 설치한 뒤 running scripts is disabled on this system 오류가 난다 PowerShell에서 Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser를 실행해 현재 사용자 범위에서 허용한 뒤 다시 실행합니다
Claude Code를 쓸 수 없다는 안내가 나온다 무료 요금제에는 Claude Code가 포함되지 않습니다. Pro 이상으로 올리거나 Pro 이상 계정으로 로그인합니다
VS Code의 터미널에서 claude가 실행되지 않는다 확장은 claude를 PATH에 등록하지 않습니다. PowerShell 설치를 합니다
확장 패널 대신 터미널이 열린다 설정 claudeCode.useTerminal을 끕니다
응답이 멈추고 움직이지 않는다 Ctrl 키와 C 키를 함께 눌러 현재 작업을 취소합니다. 그래도 안 되면 터미널을 닫고 같은 폴더에서 claude --resume으로 대화를 이어 갑니다

정리

→ 이 강의에서 한 일과 알게 된 개념을 모읍니다.

한 일

  • Windows 11과 요금제가 Claude Code 조건에 맞는지 확인했습니다.
  • PowerShell 한 줄로 Claude Code를 설치하고 claude --version으로 확인했습니다.
  • 연습 폴더 claude-first에서 claude를 실행해 로그인했습니다.
  • VS Code에 확장을 설치하고 폴더를 읽는 첫 요청을 보냈습니다.
  • claude --resume으로 확장에서 만든 대화를 터미널에서 찾았습니다.

배운 개념

  • 네이티브 설치: WSL 없이 Windows에 직접 설치하는 방식입니다. 백그라운드에서 자동으로 업데이트됩니다.
  • PATH: 명령 이름으로 프로그램을 찾는 경로 목록입니다. 설치 폴더가 빠지면 'claude' is not recognized가 나옵니다.
  • 터미널과 확장: 따로 설치되지만 대화 기록, 설정, MCP 서버, 플러그인을 함께 씁니다.
